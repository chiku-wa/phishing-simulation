# phishing-simulation

AWS 上でホスティングする、標的型攻撃メール訓練用の静的 Web サイトです。S3 を非公開のオリジンとし、CloudFront 経由で `index.html` を配信する最小構成を想定しています。

> [!CAUTION]
> 本サイトは、実施責任者の承認を得たセキュリティ訓練にのみ使用してください。認証情報、個人情報、機密情報の入力や収集を目的とした機能は実装しないでください。

## 構成

```text
訓練対象者のブラウザー
        |
        | HTTPS
        v
    CloudFront
        |
        | 非公開オリジンへのアクセス
        v
  S3 バケット
    `-- index.html
```

- S3 のパブリックアクセスはすべてブロックします。
- S3 のオブジェクトは CloudFront 経由でのみ配信します。
- サンプルページは静的 HTML のみで、入力フォームや送信処理を持ちません。

## 前提条件

- S3 と CloudFront の作成・設定ができる IAM ユーザーまたは IAM ロールがあること
- 実施範囲、対象者、期間、問い合わせ先、ログの取り扱いが事前に承認されていること
- 可能であれば、本番環境と分離した AWS アカウントを使用すること

IAM 権限は、組織のポリシーに従い、訓練環境の構築と終了処理に必要な範囲に限定してください。

## セットアップ

AWS コンソールの表示や料金プランは変更されることがあるため、作業時点の公式画面と料金表示も確認してください。以下の画像は手順作成時の表示例から、アカウント固有情報を含まない範囲だけを引用しています。

### 1. S3 バケットを作成する

#### 1-1. バケット作成画面を開く

1. AWS マネジメントコンソールにサインインします。
2. サービス検索から `S3` を開きます。
3. 左メニューの「バケット」から「汎用バケット」を開きます。
4. 「バケットを作成」をクリックします。

![S3 の汎用バケット作成画面](docs/images/s3-create-bucket.png)

#### 1-2. バケットを設定する

作成画面で、次のとおり設定します。

| 項目 | 設定 | 補足 |
| --- | --- | --- |
| AWS リージョン | 東京 `ap-northeast-1` | 東京が選択済みであればそのまま |
| バケットタイプ | 汎用 | CloudFront のオリジンとして使用 |
| バケット名前空間 | グローバル名前空間 | この構成では変更不要 |
| バケット名 | `<training-site-random-suffix>` | AWS 全体で一意の、組織を特定しにくい名前にする |
| オブジェクト所有者 | ACL 無効（推奨） | バケットポリシーでアクセスを制御 |
| パブリックアクセス | すべてブロックを ON | S3 を直接公開しない |
| バージョニング | 無効 | 最小構成。復旧要件がある場合は有効化を検討 |
| タグ | なし | 最小構成。組織の費用管理ルールがある場合はそれに従う |
| 暗号化 | SSE-S3 | 組織ポリシーで KMS が必須な場合はそれに従う |
| バケットキー | 初期値のまま | SSE-S3 を使用するため変更不要 |
| 詳細設定 | 変更しない | この最小構成では不要 |

> [!IMPORTANT]
> S3 バケット名は AWS 全体で一意である必要があります。短い一般名は使用済みの可能性が高いため、組織名や個人名ではなく、推測しにくいランダム文字列を末尾に付けてください。

#### 1-3. バケットを作成する

1. 入力内容を見直し、特に「パブリックアクセスをすべてブロック」が ON になっていることを確認します。
2. 画面下部の「バケットを作成」をクリックします。
3. バケット一覧に戻ったら、指定した名前のバケットが表示されることを確認します。

#### 1-4. `index.html` を用意する

リポジトリの [`index.html`](./index.html) を使用します。最小構成は次のとおりです。

```html
<!DOCTYPE html>
<html lang="ja">
<head>
  <meta charset="UTF-8">
  <title>Training Site</title>
</head>
<body>
  <h1>セキュリティ訓練ページ</h1>
  <p>このページは標的型訓練用です。</p>
</body>
</html>
```

ファイル名は大文字・小文字を含めて `index.html` とします。

#### 1-5. `index.html` を S3 にアップロードする

1. S3 のバケット一覧から、作成したバケット名をクリックします。
2. 「オブジェクト」タブの「アップロード」をクリックします。
3. 「ファイルを追加」をクリックし、ローカル PC の `index.html` を選択します。
4. 「ファイルとフォルダー」の一覧に `index.html` が表示されたことを確認します。
5. 画面右下の「アップロード」をクリックします。
6. アップロード成功の通知が表示され、バケット直下のオブジェクト一覧に `index.html` があることを確認します。

S3 のパブリックアクセスはブロックしているため、S3 のオブジェクト URL から直接表示できなくても問題ありません。CloudFront の設定後に表示を確認します。

### 2. CloudFront ディストリビューションを作成する

#### 2-1. CloudFront コンソールを開く

1. AWS マネジメントコンソールのサービス検索から `CloudFront` を開きます。
2. 定額プランの案内が表示された場合は、「定額ディストリビューションを作成」をクリックします。

![CloudFront の定額ディストリビューション作成画面](docs/images/cloudfront-flat-rate-plan.png)

3. プラン選択画面で「Flat-rate plans」を選択します。
4. 無料プランの「Choose 無料」をクリックします。

> [!NOTE]
> プランの名称、対象、利用上限、料金は変更される可能性があります。画面に表示される条件を確認し、組織の費用管理ルールに従ってください。定額プランの案内が表示されない場合は、当該アカウントに表示される作成フローに従ってください。

#### 2-2. 基本情報を設定する

「Get started」画面で次のとおり設定します。

| 項目 | 設定 |
| --- | --- |
| Distribution name | `<training-distribution>` |
| Description | 空欄で可 |
| Distribution type | Single website configuration |
| Route 53 managed domain | カスタムドメインを使わない場合は空欄 |

1. `Distribution name` に訓練用と分かる任意の名前を入力します。公開用の画面や手順書には実際の名前を記載しないでください。
2. 他の項目を表のとおり設定します。
3. 「Next」をクリックします。

#### 2-3. S3 オリジンを設定する

「Specify origin」画面で次のとおり設定します。

| 項目 | 設定 |
| --- | --- |
| Origin type | Amazon S3 |
| S3 origin | 「Browse S3」から手順1で作成したバケットを選択 |
| Origin path | 空欄 |
| Allow private S3 bucket access to CloudFront | ON のまま |
| Origin settings | Use recommended origin settings |
| Cache settings | Use recommended cache settings tailored to serving S3 content |

1. `Origin type` で `Amazon S3` を選択します。
2. `S3 origin` の「Browse S3」をクリックします。
3. バケット一覧から、手順1で作成したバケットを選択し、「Choose」をクリックします。
4. `S3 origin` に選択したバケットが表示されたことを確認します。
5. 残りの項目を表のとおり設定し、「Next」をクリックします。

`Allow private S3 bucket access to CloudFront` を ON にすることで、S3 をパブリック公開せずに CloudFront からアクセスできる構成にします。作成画面にバケットポリシーの更新に関する案内が表示された場合は、内容を確認してください。

#### 2-4. セキュリティ設定を確認する

1. 「Enable security」画面の内容を確認します。
2. PDF の最小構成では、表示された初期値を変更せずに「Next」をクリックします。
3. WAF などの追加機能に料金表示がある場合は、作成前に内容を確認します。

#### 2-5. 設定を確認して作成する

1. 「Review and create」画面で、基本設定、S3 オリジン、キャッシュ設定、セキュリティ設定を見直します。
2. オリジンが意図した S3 バケットであることと、S3 のプライベートアクセスが有効であることを確認します。
3. 画面右下の「Create distribution」をクリックします。

#### 2-6. デプロイ完了を確認する

1. 「新しいディストリビューションが正常に作成されました。」という通知が表示されることを確認します。
2. 作成したディストリビューションの詳細を開きます。
3. 「最終変更日」の状態が「デプロイ」となるまで待ちます。処理中の場合は、完了後に画面を再読み込みします。

### 3. デフォルトルートオブジェクトを設定する

1. CloudFront のディストリビューション詳細画面で「一般」タブを開きます。
2. 「設定」の「編集」をクリックします。
3. `Default root object - optional` に `index.html` と入力します。先頭に `/` は付けません。

![CloudFront の Default root object に index.html を設定](docs/images/cloudfront-default-root-object.png)

4. 画面下部の「変更を保存」をクリックします。
5. 「ディストリビューション設定が正常に更新されました。」という通知が表示されることを確認します。
6. 変更のデプロイが完了するまで待ちます。

### 4. CloudFront の URL で表示を確認する

1. CloudFront の「一般」タブで「ディストリビューションドメイン名」を確認します。
2. 値をコピーし、ブラウザーで次の URL を開きます。

```text
https://<distribution-domain>/
```

3. 「セキュリティ訓練ページ」と「このページは標的型訓練用です。」が表示されることを確認します。
4. ブラウザーの URL が `https://` で始まっていることを確認します。

### 5. 作業完了チェック

- [ ] S3 バケットのパブリックアクセスがすべてブロックされている
- [ ] S3 バケット直下に `index.html` がある
- [ ] CloudFront のオリジンに正しい S3 バケットが設定されている
- [ ] S3 へのプライベートアクセスが有効になっている
- [ ] `Default root object` が `index.html` になっている
- [ ] CloudFront の URL に HTTPS でアクセスできる
- [ ] 訓練ページに認証情報や個人情報を送信するフォームがない

### うまく表示されない場合

| 症状 | 確認する項目 |
| --- | --- |
| CloudFront のルート URL で `403` が表示される | `Default root object` が `index.html` か、S3 オリジンが正しいか、プライベート S3 アクセスが有効かを確認 |
| `404` またはオブジェクト不存在のエラーになる | S3 バケット直下に、正しい大文字・小文字で `index.html` があるかを確認 |
| 古い内容が表示される | CloudFront のデプロイ完了を待ち、ブラウザーを再読み込み。必要に応じてキャッシュ無効化を検討 |
| S3 のオブジェクト URL で開けない | 想定した動作。S3 は直接公開せず、CloudFront の URL から確認 |

## セキュリティと機密性

この公開リポジトリには、手順の理解に必要な最小限のサンプルだけを含めます。次の情報はコミットしないでください。

- AWS のアクセスキー、シークレットキー、セッショントークン、パスワード
- AWS アカウント ID、実在する ARN、バケット名、CloudFront ドメイン名
- AWS コンソールのスクリーンショットや、リソース名を含む操作ログ
- 訓練対象者の氏名、メールアドレス、所属、送信先リスト
- 訓練の開催日時、誘導シナリオ、結果、アクセスログなど、組織の運用や弱点を推測できる情報
- `.env`、AWS 認証情報ファイル、秘密鍵、実データの CSV、ログ、エクスポート結果

リソース名は本 README のようにプレースホルダーで表記し、実際の値は非公開の運用手順で管理してください。
